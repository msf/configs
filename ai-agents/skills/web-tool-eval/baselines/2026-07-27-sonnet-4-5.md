# Web routing baseline — Claude Sonnet 4.5

## Setup

- Executor: `anthropic/claude-sonnet-4-5`, thinking `high`
- 12 cases, one fresh `pi --mode json --no-session` process per case
- Natural prompts; no explicit `--skill`
- Normal global skills/extensions; tools limited to `read,bash,browser_read_url`
- 274.953 seconds, 21 network attempts, $0.4709664 reported model cost
- Zero timeouts and zero non-zero Pi exits

## Results

- Positive prompts causing network retrieval: 11/11
- Negative local-only control avoiding network retrieval: 1/1
- `web-tool-routing` skill loaded: 0/11 positive cases
- Usable authoritative content acquired: 8/11 positive cases
- Blocked acquisitions handled without invented content: 3/3 (Shimano, Reddit, Medium)
- Within configured network budget: 10/11 positive cases
- Strict assertion score: 36/48
- Strict whole-case score: 1/12, but this is misleading because every positive case was failed by the skill-activation assertion even when user-visible behavior succeeded

## Material findings

1. Sonnet 4.5 searched/read on every positive prompt without loading the routing skill. The extension tool description and model priors were enough for most routes; skill guardrails therefore had no effect.
2. Public GitHub content remained usable. The blob case took four retrievals because the source file contained a documentation template rather than the expanded Python example; the five-request repository-search case stayed exactly at its budget.
3. The browser extension returned two false tool successes:
   - Reddit: HTTP 200 plus `You've been blocked by network security`, `is_error=false`.
   - Medium: HTTP 403 plus Cloudflare verification, `is_error=false`.
   Sonnet recognized both and failed safely, but weaker models may not.
4. Shimano's challenge was correctly detected as a tool error. Decathlon returned usable official HTTP 200 content but did not expose the requested brake details; Sonnet did not invent them.

## Evaluation correction

Skill activation should be reported separately, not make every otherwise-successful case fail. The primary score should be user-visible retrieval, grounding, safe failure, and route efficiency. Skill activation remains diagnostic because skipped skill guidance can explain inefficient routing.
